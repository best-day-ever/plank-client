# Apple preview decoder fixture

`applevideo-test-frame.h` embeds one synthetic PLANK chart frame generated by
the dedicated development Mac's VideoToolbox HEVC encoder on macOS 27 beta.
It contains no user desktop capture. The 3338-byte Annex-B payload SHA-256 is
`d04c41f03737442f57523e7d009c2c0fb16db9543090c468d1bd563388ff8b60`.
Trailing zero padding is outside the packet length.

The pinned Client FFmpeg reports Main 10, 3840x2160, `yuv420p10le`, limited
range, BT.709 matrix/primaries and IEC 61966-2-1 (sRGB) transfer. This proves
encoded format and metadata, not native ten-bit ScreenCaptureKit source
precision, visual fidelity, hardware decoding, performance or presentation.
Beta-generated results need revalidation on the final OS.

Build this uninstalled test only on linux-client-builder. Set `PKG_CONFIG_PATH` to the
retained private FFmpeg's `install/lib/pkgconfig`, run `qmake6` on this `.pro`
in a separate build directory and `make`. Run with `LD_LIBRARY_PATH` pointing
to that same private FFmpeg's `install/lib`. No package installation or network
session is required. It decodes the real test packet and exercises the shared
color/precision rejection function. Synthetic hardware-storage metadata tests
are explicitly not a substitute for decoding on an Intel test target.

The actual FFmpeg renderer initialization uses this frame only for the explicit
ScreenCaptureKit profile, with its true 4K dimensions. Existing Linux identity
fixtures remain unchanged. A live Apple stream is checked before presentation
and disconnected if its format/color contract changes. Mac launch remains
disabled until authenticated native media and service negotiation are ready.
